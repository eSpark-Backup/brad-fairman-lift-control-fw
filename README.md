# bradfairman-liftcontrol-fw

## Project Requirements
*1. Simplified code:* with unused functions and components removed. At first we were going to add sensors to the electronics to help with safety.   However we could not get the sensors to work properly so we remove these.  However the code was commented out and really should be properly removed.  The whole code needs to be refactored so we dont have dead code in there. We had two time of flight sensors that would measure the distance of the actuator from the top of the frame of the display.  However we removed this requirement as it was cumbersome (unnecessary and complex).  We also designed a human interface sensor but we had issues with I2C and properly getting values from the human interface sensor so we removed it as well.
*2. PID routine review:* to determine if any of the suggested improvements should be implemented to enhance performance.  We have recommendations for making the PID routine better (motor extend and retract routine - sync motors). Some AI generated info and document is added in docs folder as received by client.
*3. Current sensing and fault detection:* with logic to stop the motors if current exceeds a threshold. The actuators max out at 2.9A (total) during lift, though typical draw is between 1.2 - 1.5A each. We want to add current sensing so that we can set a threshold so that if the current exceeds a certain limit WE ASSUME something is wrong and we shut down motors to stop any damage from occurring.   If this happens the unit should reset and actuators should travel to the home position (fully retract).
*4. GPIO output triggered by the beam break sensor* when an obstruction is detected, allowing us to display a video or image to explain the stoppage. Currently we use a simple IR beam break sensor to determine if an object is in the way of the lift retracting.  We only use the sensor for when the lift is coming down.  However we want to confirm the status of the beam break on boot and also before the lift goes up as its better logic to make sure the beam is working before starting the lift procedure and finding out its not working and causing a fault while the lift is in the full travel (fully extended position).
*5. Beam break sensor check on boot and prior to upward travel*. We’ve seen actuators fall out of sync in two scenarios:
    - One actuator encountered significant force, likely triggering a fault.
    - The beam break sensor was not connected to the electronics.
*6. Reset routine* where both actuators return to the home position and the media player is instructed to restart from the beginning.  IE adding a pushbutton or using the touchpad for a reset.  IE hold touchpad for 15 seconds or something. We want to add a mechanism for rebooting the entire display.  This means adding a pushbutton or similar to the electronics.  We currently have extra connections to the MCU as we are not using any of the ToF or the HPD (human presence detector).  Else maybe utilize the cap touch pad for reset.  A routine.  IE touch once, wait 3 seconds touch again, eait 3 seconds press and hold for 15 seconds)  something like that.  This routine would trigger a hard reset and the lift would go back to the home position.  This is needed in case anything goes wrong in the field.  As we will not have access to the power cords to cut power.
